# MNIST 全连接网络 baseline

大一寒假自学深度学习时写的第一个模型，用于跑通「前向 → 损失 → 反向 → 更新」的完整链路。原始代码与提交时间见 [issue #1](../../issues/1)。

## 结构

```
输入 (batch, 784)
  ↓ Linear(784→64) + ReLU
  ↓ Linear(64→64)  + ReLU
  ↓ Linear(64→64)  + ReLU
  ↓ Linear(64→10)  + LogSoftmax
```

约 5.9 万参数。Adam，lr=1e-3，batch_size=15，训练 2 个 epoch。

原始版本没有固定随机种子，每次运行的准确率都有约一个百分点的波动。现已加上 `torch.manual_seed(0)`——参数初始化和 DataLoader 的打乱顺序都取自全局随机数生成器，不固定就无法复现，也没法判断改动带来的差异是真实的还是随机的。

## 运行

```bash
pip install torch torchvision
python mnist_mlp.py
```

首次运行自动下载 MNIST。

## 结果

| 阶段 | 测试集准确率 |
| --- | --- |
| 训练前 | 10.19% |
| epoch 1 | 95.26% |
| epoch 2 | 96.69% |

训练前的 10.19% 即 10 分类随机猜测水平。第 1 个 epoch 提升约 85 个百分点，第 2 个只再提升 1.4 个百分点，收益迅速收窄。

## 当时的探索与现在的修正

试过加深网络，测试准确率未提升甚至略降；试过延长训练，收益同样有限——上表第 2 个 epoch 的 1.4 个百分点即是这一趋势的开端。

当时把前者归因于过拟合。现在回看，这个判断没有证据支持：`evaluate()` 只在测试集上运行，全程未统计训练集准确率，而过拟合的判据是训练集显著高于测试集。仅凭测试准确率下降，无法区分过拟合、欠拟合与优化困难。

更可能的原因是优化难度。朴素 MLP 每加一层，梯度回传更困难；在没有残差连接和归一化的条件下，加深的优化代价超过表达能力的收益。

延长训练收益有限则受限于结构：展平成 784 维向量丢失了像素的空间信息，全连接网络在 MNIST 上的上限约 98%，继续提升需要卷积。

## 现在会改的地方

1. 同时统计训练集准确率。只看测试集等于放弃诊断能力，即上一节的教训。
2. batch_size 从 15 调大到 64 或 128。过小的 batch 使 Python 开销摊不下去，训练时间大部分耗在数据加载，梯度噪声也偏大。
